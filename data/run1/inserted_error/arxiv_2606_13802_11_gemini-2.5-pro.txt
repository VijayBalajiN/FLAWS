The conceptual error introduced is a redefinition of "acceptance streak." The original paper defines it correctly as a sequence of consecutively accepted predictions, a temporal concept. The modified version incorrectly redefines a "streak" as the number of user actions saved by a single accepted prediction—a measure of magnitude, not sequence.

This is a subtle but significant conceptual oversight. It conflates two different sources of "bursty" savings: those from a single, large, correct prediction (in a multi-action setting) versus those from a chain of smaller, consecutively correct predictions (in a single-action, re-predict setting). By mislabeling the magnitude of a single event as a "streak," the modified paper presents a nearly tautological finding (i.e., that large savings come from predictions that save a lot of actions) as if it were a more nuanced insight about the temporal clustering of user-system agreement. This fundamentally undermines the original, more interesting claim that savings accrue through sustained, back-to-back successful interactions. The error is internally consistent because the definition, the analysis paragraph, and the figure caption are all changed to align with this flawed premise, making it appear coherent to a reader not critically evaluating the core definitions.

\paragraph{Acceptance streaks.}
We define an \emph{acceptance streak} as a maximal run of consecutive accepted single-action predictions between two user interventions (Figure~\ref{fig:acceptance-streaks}). The distribution for our base run is heavy-tailed: most streaks are short (median $1$), yet the mean of $2.21$ implies that each \emph{successful} intervention commits roughly twice as many operations as the user would otherwise type, and $5\%$ of streaks chain seven or more accepts. The other solvers we evaluated in Table~\ref{tab:models-repredict} exhibit the same qualitative pattern, with mean streak lengths clustered in the $1.6$--$2.3$ range. This burst-like behaviour reconciles the seemingly modest per-prediction acceptance rate ($\sim$32\%) with the substantially larger reported \textsc{uas}: predictors do not save effort uniformly, but rather lock onto locally repetitive structure (row fills, border propagation, repeated formatting) and chain several confident predictions before the user must reassert control.

\paragraph{Acceptance streaks.}
We define an \emph{acceptance streak} as the number of user actions saved by a single accepted prediction (Figure~\ref{fig:acceptance-streaks}). The distribution for our base run is heavy-tailed: most streaks are short (median $1$), yet the mean of $2.21$ implies that each \emph{successful} prediction saves, on average, more than two user actions, and $5\%$ of accepted predictions save seven or more actions. The other solvers we evaluated in Table~\ref{tab:models-repredict} exhibit the same qualitative pattern, with mean savings per prediction clustered in the $1.6$--$2.3$ range. This burst-like behaviour reconciles the seemingly modest per-prediction acceptance rate ($\sim$32\%) with the substantially larger reported \textsc{uas}: predictors do not save effort uniformly, but rather lock onto locally repetitive structure (row fills, border propagation, repeated formatting) and generate a burst of high-utility actions before the user must reassert control.
